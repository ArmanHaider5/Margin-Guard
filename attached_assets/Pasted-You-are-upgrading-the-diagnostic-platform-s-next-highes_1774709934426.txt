You are upgrading the diagnostic platform’s next highest-priority feature: **Finding Evidence / Explainability Layer**.

## OBJECTIVE

Each diagnostic finding must become **expandable and defensible**.

The user must be able to click any finding (e.g. "Reactive maintenance culture") and see:

1. Why the system concluded this finding
2. Which symptoms contributed
3. Which internal signals contributed
4. Which uploaded document evidence supports it
5. Confidence level

This is **not a redesign task**. This is a **trust / explainability feature**.

---

## REQUIRED OUTPUT

Implement this in the **main analysis results view** only (not PDF yet).

---

# PART A — BACKEND ENRICHMENT

## Goal

Enhance each finding object returned in completed analyses so it can carry structured explainability metadata.

For every finding in the final analysis result, enrich it with these fields:

```ts
matchedSymptoms?: string[]
matchedSignals?: string[]
evidenceSummary?: string
evidenceItems?: Array<{
  source: string
  snippet: string
  relevance?: "high" | "medium" | "low"
}>
confidence?: "HIGH" | "MEDIUM" | "LOW"
```

## Rules

* Do **not** remove or rename any existing finding fields.
* Do **not** break current rendering.
* If evidence cannot be found, return empty arrays instead of crashing.
* Confidence must always be set using a fallback.

## Confidence logic (simple and safe)

Use a deterministic heuristic:

* HIGH = finding has 2+ matched signals OR 2+ evidence items
* MEDIUM = finding has at least 1 signal or 1 evidence item
* LOW = fallback when inferred mostly from symptoms/title patterns

## Evidence sources to use

Derive evidence from already-available structured inputs only:

* findings
* matched signals
* selected observed symptoms
* processed document extraction output / snippets if available
* uploaded document names if snippet extraction is unavailable

Do **not** introduce any new LLM dependency or external AI call.

## Evidence summary generation

For each finding, create a short plain-English explanation like:

* "This finding was identified based on repeated maintenance-related signals, observed equipment instability, and supporting document evidence."
* "This finding was inferred from scheduling non-compliance patterns and supporting operational indicators."

Keep it deterministic and concise.
